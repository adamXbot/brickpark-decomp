## Method notes (new evidence, not promotions)

### Joust_Update — cross-jump into `jne`

Original at indices 670–673 (exiled after `ret`):

```
cmp dl, 1 / je stop / cmp dl, 3 / jmp 0x40841e
```

`0x40841e` is the **inline** horse-1 path’s `jne run` at index 628, immediately
before the single `mov ebp, 1` (`set20`). So the exiled arm shares both the
conditional and `set20` by jumping *onto* the `jne`, using flags from `cmp dl,3`.

Our body emits `cmp dl, 3 / je …` instead (`+1` byte at the only normalized
mismatch). A tree scan of the four documented block-exile exact bodies found
**zero** other `cmp / jmp → jcc` hits; this encoding remains once-in-binary.

Tried (all worse or inert on the 1-mismatch baseline): move `set20` into the
fall-through arm; duplicate `f20 = 1`; invert `cycle == 0`; positive busy
predicate; both arms `goto set20`; `else if (h == 3)` form. Retained source
unchanged.

### Coaster3D_BuildTrackMesh — push ownership

Original element window:

```
mov edx,[hooks] / mov ecx,[list] / lea eax,&dir / mov esi,ecx / mov [home],ecx / …
push eax / push esi
```

Volatile read still gives allocation order at the cost of `mov esi,[home]`
(6 mismatches / 442 B). Plain record / named `e` / intervening `&dir` /
hooks-first / volatile store all fall into the 438–441 B / ~122 family where
the scratch owns the first push. No new spelling produced register-copy-before-
store without the volatile barrier. Scratch: `mesh_probe.py`, `mesh2_*.json`.

### LFEntrance_Activate — qx-before-next

Baseline remains next-first → `add` not `lea` (10 / 672).

- `next = *(RiderNode* volatile*)&r->next` after the tx sum: **8 mismatches /
  672 B** (known “next late” local optimum from the prior note; not the
  original’s early-next + long range + `lea`).
- Comma sequencing, named `qx`, identical-arm joins, empty `if (next)`, and
  arithmetic no-ops (`tx += (int)next & 0`, `* 0`, `n - n`) are all inert or
  fold to baseline — VC6 deletes the second use when it has no effect.
- The documented semantics-changing `tx += (int)next & 1` probe still proves a
  long next range can force original packing; no semantics-preserving substitute
  found this pass.
- Forcing `qx` into the `next` address (`(char*)r + (qx&0)`, `qx*0`, `qx-qx`,
  comma `(def->qx, r->next)`) either stays at 10 or jumps to ~95 / 675 B.
