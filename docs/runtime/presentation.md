## 1. Shared records and coordinate conventions

The map, screen and game views at `0x004bcbf4` are one record: screen width/height are `u16` at `+0/+2`; viewport width/height are at `+0x10/+0x12`; map width/height at `+0x14/+0x16`; viewport pixel origin at `+0x20/+0x22`. Cells have stride `0x14`, object element at `+0`, packed owner square at `+4/+5`, packed next render-chain square at `+6/+7`, and flags at `+0xc`. The next-square zero pair terminates a map chain; these links are coordinates, not heap pointers. [surface.c](../../LEGOLAND/surface.c), [renderview.c](../../LEGOLAND/renderview.c), [powerhelp.c](../../LEGOLAND/powerhelp.c)

World walking positions use 24.8 fixed point, with 256 units per map tile and `0x80` at tile center. Scroll globals `0x00667cb4/0x00667cb8` also have eight fractional bits, but their integer portions are **screen pixels** in the renderer. `scroll.c` calls them “8.8” and its getters “whole tiles”; the projection subtracts `scroll >> 8` directly from pixel coordinates, so “whole tiles” must not be used as the runtime unit. `OverNewTile` detects a change above bit 7; `CrossTileCentre` detects bit 7 changing without a tile change. [tilehelp.c](../../LEGOLAND/tilehelp.c), [scroll.c](../../LEGOLAND/scroll.c), [scrolltick.c](../../LEGOLAND/scrolltick.c), [renderview.c](../../LEGOLAND/renderview.c)

With default ground-sprite height `h`, tile width is `w=2h` (shipped tiles: 32×16). Tile bounds are `left=((w+1)>>1)*(tx-ty-1)-(scroll_x>>8)+origin_x`, `top=((h+1)>>1)*(tx+ty)-(scroll_y>>8)+origin_y`, `right=left+w-1`, `bottom=top+h-1`. The center uses `(tx-ty)` and `(tx+ty+1)` instead. Object/layer pixel offsets are stored at twice drawing scale and halved toward zero, including negative values. Rectangle chains count inclusive cells: area is the sum of `(right-left+1)*(bottom-top+1)`, without subtracting overlap. [renderview.c](../../LEGOLAND/renderview.c), [tilehelp.c](../../LEGOLAND/tilehelp.c), [math3d.c](../../LEGOLAND/math3d.c), [rect.c](../../LEGOLAND/rect.c)

## 2. Input, menus and help state machines

### Input and focus

Each system tick drains Windows messages, scans keyboard, scans mouse, applies mouse data, then keyboard data. Mouse deltas can be doubled at each enabled acceleration stage before clamping x/y to `[0,screen-1]`; prior x/y and effective deltas are retained. The game-button fold produces press/release/held edges, a 200 ms initial repeat followed by 50 ms repeats, cursor/map-reference bookkeeping, and a 2-second idle flag. `WM_KILLFOCUS`/`WM_CANCELMODE` freeze and suspend; focus return thaws only if the clock was not frozen before focus loss. The message pump waits while inactive. `WNDENV` only stores/returns native HWND and HINSTANCE, at `0x00669210` and `0x00669208`. [input.c](../../LEGOLAND/input.c), [input2.c](../../LEGOLAND/input2.c), [bighelp.c](../../LEGOLAND/bighelp.c), [wndenv.c](../../LEGOLAND/wndenv.c)

| Controller bit | Binding | Source |
| --- | --- | --- |
| `1,2,4` | Mouse buttons 0,1,2 | [input.c](../../LEGOLAND/input.c) |
| `8,0x10,0x20,0x40` | Left, right, up, down (`DIK cb,cd,c8,d0`) | [input.c](../../LEGOLAND/input.c) |
| `0x80,0x100,0x200,0x400` | Space, Tab, Escape, Return (`DIK 39,0f,01,1c`) | [input.c](../../LEGOLAND/input.c) |

The mouse fold clears only `0x7`; the keyboard fold clears only `0x7f8`, preserving higher bits. The 59-pair character map at `0x004bad58` returns the last newly pressed mapped key, with letters lowercased unless Caps Lock XOR Shift requests uppercase. Decoded special values are Up/Left/Right/Down `-11/-12/-13/-14`, Backspace `-1`, Escape `-2`, Return and numpad Enter `-3`, Caps Lock/Shift `-10`. Printable input is also appended to a 20-byte cheat ring and its suffix compared with `:WORD` codes. [input.c](../../LEGOLAND/input.c), [input2.c](../../LEGOLAND/input2.c)

Arrow scrolling requires input flag `0x20` and held-bit 4. X steps are twice the Y step; independent horizontal and vertical pairs allow diagonals, while left wins over right and up over down. A held direction returns 1 and suppresses mouse-edge scrolling. Mouse-down in edit mode 2 with a class selects its footprint, uses inclusive footprint width/height as drag strides and biases the drag origin by the class corner; otherwise it latches the hovered map square. Consuming the initial press sets drag flag `0x1000`. [mapscreen4.c](../../LEGOLAND/mapscreen4.c), [lanes/fable-c-mapscreen4.md](../lanes/fable-c-mapscreen4.md)

The icon input ABI has four arguments `(icon, buttons, dx, dy)` and a char result. UI comments call bit 2 “click” or “release”; the underlying button state defines it as released this tick. Most handlers return 1 even when idle; actions commonly return 2, including free-play and volume actions. Input routing tries the global handler, then the focused icon/default handler with icon-local offsets, then the fallback handler; secondary events are used during dragging and when no button is active. Hit scanning chooses the last enabled, sized hit on either list. A clip icon gates subsequent icons; custom-hit icons can reject a hit unless its `0x800` group relation is the custom group plus 2 or 3. [screens3.c](../../LEGOLAND/screens3.c), [bighelp.c](../../LEGOLAND/bighelp.c), [fpui.c](../../LEGOLAND/fpui.c), [fpui2.c](../../LEGOLAND/fpui2.c)

Indicators move between inactive/active singly linked lists `0x006688d4/0x006688d8`; bit `0x8` records activity and bit `0x1` prevents timeout. Each update rebuilds active order by descending key, expires timed records, then lays survivors right-to-left at 52-pixel spacing, parking those that would cross the left quarter of the screen. Indicator icons belong to group `0xe000`. [iconui.c](../../LEGOLAND/iconui.c), [fpui2.c](../../LEGOLAND/fpui2.c)

Nine tutorial flash flags redraw theme/tool buttons at their fixed table positions only in running-park game mode 3, independently of whether an icon remains there. Blink selects pressed/normal artwork; sound fires when flashing begins on a lit phase. Clicking a class checks affordability first, buzzes on refusal, otherwise selects build mode when icon flag `0x1000` is set, clears NEW flag `0x20000`, removes its NEW-strip entry and returns 2. [fpui4.c](../../LEGOLAND/fpui4.c)

### Side panel and free-play

The side panel slides groups `0xd2,0xd5,0xd6,0xd7`. Its per-frame step is elapsed milliseconds capped at 990, multiplied by `5/33`, then passed as a **signed char**. Because that maximum quotient is 150, the byte narrowing must be retained when reproducing long-frame behavior. [fpui.c](../../LEGOLAND/fpui.c), [fpui3.c](../../LEGOLAND/fpui3.c)

| State | Rule and transition | Source |
| --- | --- | --- |
| 0, sliding in | Move icons right; when kind `0xa` list icon passes x=3, snap it to x=0, adjust remaining movement, set state 3, commit viewport width `0x207=519` and move its origin/scroll boundary by `0x79=121` pixels | [fpui3.c](../../LEGOLAND/fpui3.c) |
| 1, sliding out | Move left; beyond `-0x7a=-122`, set state 2, marker byte `0x86`, free list icons. Before arrival clamp map scrolling to follow the edge | [fpui3.c](../../LEGOLAND/fpui3.c) |
| 1 with committed latch `+8` | First matching icon restores 640-wide viewport and returns immediately; state stays 1 and normal slide resumes next frame | [fpui3.c](../../LEGOLAND/fpui3.c) |
| 2 / 3 | Fully out / fully in; no sliding work | [fpui3.c](../../LEGOLAND/fpui3.c) |

`ScrollIconPanel` first snaps a fitting icon extent flush to the box origin. Otherwise **SnapIconScroll always receives vertical geometry and dy**, including horizontal panels. Vertical panels clamp that snapped y step; horizontal panels clamp the original dx instead, but still apply the snapped y step and advance saved menu scroll by it. This corrects the file header's broader claim that the selected axis is snapped; the function-specific note and body expose the asymmetry. Only the selected axis is clamped. Scroll buttons act on press and repeat every 250 ms while held, by 6 units vertically or `0x20` horizontally, with the down button negating both. [fpui4.c](../../LEGOLAND/fpui4.c), [fpui3.c](../../LEGOLAND/fpui3.c)

Menus are four 20-byte LLIDB names at `0x004bafa8`; index 5 means none. Menu index order is LEGOLAND 0, WESTERN 1, CASTLE 2, ADVENTURERS 3, whereas closed-flag order is LEGOLAND, CASTLE, WESTERN, ADVENTURERS at `0x004bb094`. Submenus at `0x004baffc` are SCENERY MENU, FOOD STORES MENU, SHOPS MENU, ATTRACTIONS MENU. ObjDef `+0x58/+0x5c/+0x60` select parent/theme/submenu. Opening the active theme closes it; opening another rebuilds objects and lights its button. COMMON THEME belongs under menu 0. Failed opens restore the old menu except for the Adventurers bug recorded below. [screens3.c](../../LEGOLAND/screens3.c), [fpui2.c](../../LEGOLAND/fpui2.c)

Top-level object nodes sort cheapest first, inserting after equal-price incumbents. Children sort among siblings after their parent; absent-parent children are discarded or added alone in list mode. Expanded parents have element flag 8 and show child runs; collapsed parents show a list bar instead. Class icons stand 66 pixels apart, dim when unaffordable and flash while NEW flag `0x20000` remains. R&D lists include DLL-backed classes (`0x10000`); unreached classes gain research flag `0x04000000` unless either `0x04000000/0x08000000` is already set. [fpui.c](../../LEGOLAND/fpui.c), [fpui2.c](../../LEGOLAND/fpui2.c), [fpui5.c](../../LEGOLAND/fpui5.c)

The free-play table at `0x004bdeb8` consists of 133 16-byte rows `{id,name,cost,chosen}` plus a sentinel row whose **name points to an empty string**. Walks stop on string length zero, not a null pointer or fixed count. `fpui2.c`'s `0x86` entries agrees when the sentinel is included. Names compare case-insensitively; absent names cost zero and yield no row. Decoded prices: HEDGE 32, PALM TREE 27, WATERPUMP 59, WATER WORKS WATER BLOCK 171. The full table is not decoded by these headers. [fpui2.c](../../LEGOLAND/fpui2.c), [fpui5.c](../../LEGOLAND/fpui5.c)

### Text, advisor and mission help

Text printing unlocks the draw surface, borrows its GDI DC, clips to `0x004bdea0`, selects one of four fonts, draws, restores selected objects and restores the prior lock state. `InfoPrintCent` assumes the caller already unlocked. Ordinary centered boxes are 400 pixels tall; single-line `PrintCent` uses a 1280-wide box. The cached-text identity is `(text,format,ink,paper,font)` and **omits requested width**; w/h are measured output, so differently constrained calls can reuse one rendering. [text.c](../../LEGOLAND/text.c), [fpui3.c](../../LEGOLAND/fpui3.c)

Bubble help centers on its anchor, clamps to the screen and prefers above the anchor, switching below when necessary. The SPEECH BUBBLE element's six pieces are `[0] up tail, [1] down tail, [2] top-left, [3] top-right, [4] bottom-left, [5] bottom-right`. Hover anchors double the mouse point and raise the top 10 pixels. Accepted advisor text is copied and timed; existing advisor help refuses a new item. Object-help queue head `0x00668724` uses `0x44`-byte ScriptEvents. Text is split destructively at `@` into bubble text and speech filename; media playback is stopped/restarted around narration and face state becomes 4. Queue removal waits for acceptance, so a refused entry stays queued but its stripped narration suffix does not replay next tick. [bighelp.c](../../LEGOLAND/bighelp.c), [iconui.c](../../LEGOLAND/iconui.c), [fpui5.c](../../LEGOLAND/fpui5.c)

Mission help ticks every 200 ms. Event head `0x00668784` holds `0x44`-byte records with text `+8`, kind `+c`, flags `+10`, last-service time `+3c`. Kind indexes handler table `0x004b9d44` and dirty-mask table `0x004b9e5c`; null handlers remain inert. Events become due for a new step, matching dirty bit or more than 5000 ms since service. Handler success deletes events with `(flags&7)==0`, otherwise marks done (`0x80`); handler failure also marks done when flag 4 is set, otherwise clears done and counts the event live. ## 4. Assets, frame lifecycle and sprite pixels

### Sprite residency and formats

Sprite flags include `0x10` system memory, `0x20` function drawing, `0x80` magenta color key, `0x400` resize pending, `0x8000` ILF composite. Detail-dependent images have kind 1 and register in table `0x0079a7c4` with cap/count `0x0079a7c8/cc`. Print front-ends ensure residency; a missing surface is created/recreated before rasterizing. Function sprites call their draw callback into a redirected target. Surface allocation prefers video memory unless system-memory flagged, then falls back to system memory with one Compact/retry; lost image data can be re-decoded. Sprite/image references are independent; the last sprite reference releases its surface and owned image or ILF table, except borrowed function data. [sprite2.c](../../LEGOLAND/sprite2.c), [spritemisc.c](../../LEGOLAND/spritemisc.c), [render2.c](../../LEGOLAND/render2.c)

`.lls/.llz` are loaded whole through RES; the header's frame resets to 0 and delay/timer to 4. Format 8 selects ImageRec type 2; otherwise type 3 (format `0x10` frame table). BMP supports only uncompressed 8-bit or 24-bit bottom-up images with assumed 40-byte info header; source stride is `(width*bpp/8+3)&~3`. The 8-bit path preserves padded rows but swaps only width bytes when flipping; its palette allocation is `0x208` bytes with 256 u16 colors starting at +4. The 24-bit path produces width×height×2 bytes while flipping. Depth selector 2 packs 565, otherwise 555: `((r&0xf8)<<8)|((g&0xfc)<<3)|(b>>3)` versus `((r&0xf8)<<7)|((g&0xf8)<<2)|(b>>3)`. Negative-height and V4/V5 BMP handling are not supported by this loader. [screen.c](../../LEGOLAND/screen.c)

`.csp` is little-endian: u16 layer count, discarded u16, u32 header length then discarded header bytes, `count` pairs of s32 dx/dy, then `count` entries `{u32 name_length; name bytes}`. Names are not NUL-terminated in the file. The loader reads `.\CompSprite\<name>`, recursively loads each layer using the caller's kind, stores the arrays in a `0x24`-byte ILF descriptor and sets sprite `0x8000`. Animated type-2/3 layer images automatically start. Rendering walks layers in order at half offsets and skips sprite flag `0x4000`; `PrintSpriteEx` also applies its bit-per-layer mask. [render3.c](../../LEGOLAND/render3.c), [sprite2.c](../../LEGOLAND/sprite2.c), [printlist.c](../../LEGOLAND/printlist.c)

LLS playback has a global `{lls,next,owner}` list at `0x006691ac`; play is idempotent, stop unlinks, play-once sets flag 4. Each `LLSAuto` call subtracts 2 from timer, advances/reloads when due, and on play-once wrap clears that flag and removes the node. Frame setters clamp to `[0,count−1]`. `LLS555To565` rewrites palettes as `((c&0xffe0)<<1)|(c&0x1f)`: format 8 has one palette after pixel data; format `0x10` walks count plus base-image flag frames and their palette/control entries. Layer accessors forward through the layer sprite's image holder without validating the layer index. [layervis.c](../../LEGOLAND/layervis.c), [layers.c](../../LEGOLAND/layers.c)

### Frame and target state

The DirectDraw host spans `0x00667d70..0x00668148`: v1/v2 objects `0x667d70/74`, driver/HEL caps `0x667d78/0x667ef4`, primary `0x668070`, draw surface `0x66807c`, clipper `0x668080`, lock descriptor `0x66809c`, drawing clip `0x668108`, target stack index `0x668118`, ten targets `0x66811c`, locked flag `0x668144`. The independent status stack holds 32 lock flags at `0x668164` with index `0x6681e4`. Push/pop restores the previous lock state; target push/pop unlocks around redirecting to a sprite surface. [gpu.c](../../LEGOLAND/gpu.c), [surface.c](../../LEGOLAND/surface.c)

Lock recalculates clip by intersecting caller clip with `{0,0,w−1,h−1}`, then locks with WAIT|WRITEONLY, restores/retries once on lost surface and refreshes the transparent key. The original mixes inclusive game bounds with Win32's exclusive rectangle intersection. `DDSURFACEDESC` is `0x6c` bytes; byte pitch is `+0x10` (`0x6680ac`) and pixel pointer `+0x24` (`0x6680c0`), not independent globals. Unlock also restores/retries and reloads pointers. Text/hardware blits require unlocked state, software painters locked state. [surface.c](../../LEGOLAND/surface.c)

`RenderScreen` updates volume and game buttons, locks, draws backdrop/icons/front-end help, restores status, then calls `RenderingComplete`. Completion pumps events, expires text cache and calls presenter `0x004b9ca4` (initial `0x00466080`) for LLS advance, cursor, frame throttle and Flip. It does not itself pop the status stack. `RenderBlock` unlocks, attaches the clipper, performs WAIT|COLORFILL and restores state; a wholly clipped fill succeeds. Scaled/tiled rendering caches a system-memory scratch surface at `0x0079861c` sized to the primary, paints there in software and asks DirectDraw to stretch it onto the draw target. [render2.c](../../LEGOLAND/render2.c), [gpu.c](../../LEGOLAND/gpu.c), [bigrender.c](../../LEGOLAND/bigrender.c)

`GenerateNewImageFromZBuffer` temporarily points the lock descriptor at static u16 scratch `0x0066be54` with pitch 2w, software-draws a sprite and builds a second u16 image at `0x00701e68`: pixels whose Z is above threshold become transparent. It returns a static sprite `0x00701e64` over static image descriptor `0x0066be50`, then restores the original lock/clip. Its returned storage is shared between calls. Target-stack underflow is fatal `exit(2)`. [gpu.c](../../LEGOLAND/gpu.c)

### Depth lists and hit tokens

Print nodes bump-allocate from arena `0x007cb600` using byte cursor `0x0066b5a8`. `InsertPrintItem` keeps **ascending** key order and begins searching from the last inserted node, moving backward/forward as required; equal keys insert after its current equal cursor. The flush walks `next`, dispatches type 0 sprite, 1 clipped sprite, 4 sprite+callback or `0x2000` person, and resets the arena. Palette/frame overrides are captured when queued and reinstated for the deferred draw, rather than sampled at flush time. [printlist.c](../../LEGOLAND/printlist.c), [workorder3.c](../../LEGOLAND/workorder3.c)

The separate 16-byte RenderItem lists use arenas `0x00630108/0x00638218`, cursors `0x0062feec/f0`, counts `0x00655a4c/50`. Both `RenderItem_Link` variants insert before the first node whose key is greater **or equal**, so order is ascending and a new tie precedes older ties. The `renderlist.c` header's “descending/largest head” conclusion contradicts both bodies and is corrected here. Do not confuse these lists' tie behavior with PrintNode insertion. People with `flags62&0xa0` are excluded from normal sorting; seat drawing selects slots at owner `+0xcc` whose u16 seat `+0xc` matches the requested index and whose bloke is not `0x80`-suppressed. Workers exclude `0x20`; the second worker list additionally requires nonzero `+0x46`. [math3d.c](../../LEGOLAND/math3d.c), [renderlist.c](../../LEGOLAND/renderlist.c), [render2.c](../../LEGOLAND/render2.c)

`PrintSprite` mode 0 selects plain rendering and other modes select recoloring. After any drawn pixel/run covers the mouse address, the blitter sets hit flag `0x007feb14`; PrintSprite copies its caller's BlitCtx to `0x004bdd00` unless kind `0x100` suppresses ownership. This is pixel coverage, not just bounding-box selection. Palette override is at `0x006681e8`, frame override at `0x004b9ca8` (`−1` means none); callers clear them after their intended drawing interval. [printlist.c](../../LEGOLAND/printlist.c), [sprite_override.c](../../LEGOLAND/sprite_override.c), [softblit.c](../../LEGOLAND/softblit.c)

### Software blits and animation streams

All CPU sprite output is 16 bpp at `base+y*pitch+x*2`, pitch in bytes. Plain raw type 0 expands indices through palette+4 with source stride `(w+3)&~3`; other non-animation types use raw u16 stride `2w`. Both skip the transparent color; recoloring additionally ANDs pixels with the 16-bit recolor mask. Function-drawn sprites are temporarily locked and described by a synthetic raw ImageRec whose width is pitch/2. Atlas origins are added to the **caller's source rectangle in place**. Recolor type 3 with color bit 31 uses the highlight painter with mask `~GetNearestColour(15,15,15)`. [softblit.c](../../LEGOLAND/softblit.c), [bigrender.c](../../LEGOLAND/bigrender.c)

Type-2 animation frames have total byte length at `+0`, index-block byte length at `+4`, index data at `+8`, then—only in frame 0—a 512-byte palette, then control words. Controls consume 2-bit codes, LSB first, 16 per u32: bit1 clear is a literal; binary 10 skips one; binary 11 introduces an 8-bit count, zero ending the row. A second code picks skip (bit1 set), literal run (00) or repeated index (01). Transparency resides in controls. Clipping first skips top rows, then left pixels, paints width and consumes the row remainder, splitting runs at clip boundaries. [softblit2.c](../../LEGOLAND/softblit2.c), [softblit.c](../../LEGOLAND/softblit.c)

Type-3 RLE frames have total bytes `+0`, count of 16-bit control entries `+4`, length of u16-pixel block `+8`, data at `+0x10`: controls, 16-bit block, then 8-bit block. The dispatcher biases destination x by `−src.left` and passes clipping through shared globals. Plain type-3 chooses among eight painters by clip/mouse geometry; recolor always uses its single frame painter. The mouse bounding box in plain RLE is inclusive through x+w/y+h, an off-by-one broad-phase test. Shared scratch, including recolor `0x7fe998`, mouse pixel `0x7fe9a8`, row step `0x7fe9a4`, palette `0x7fea20`, clip top/left `0x7fea4c/50`, clip h/w `0x7febac/b0`, is not reentrant. [render3.c](../../LEGOLAND/render3.c), [softblit2.c](../../LEGOLAND/softblit2.c), [softblit.c](../../LEGOLAND/softblit.c)

Frame selection normally chooses nonnegative override, otherwise record frame, then clamps to count−1. ## 5. World view, terrain and software 3D

### World drawing order and terrain

The world view performs five phases: repaint terrain; gather distinct visible object owners; run per-class pre-render hooks; queue object sprites with depth/clip keys; queue people/workers, flush, then draw construction effects, edit cursor and worker interface. Ground is forced fully dirty before painting and its dirty flags are cleared afterward. Gathering visits two half-offset cells per diamond column, moving map `(x+1,y−1)` per column and `(x+1,y+1)` per row. Cells with flags `0xa0` contribute their owner; owner flag `0x400` deduplicates, then is cleared during queuing. Collection is a 3000-entry local array without a capacity check. [renderview.c](../../LEGOLAND/renderview.c)

For footprint `{left,top,right,bottom}`, corner A=`(base.x+left,base.y+bottom)` and B=`(base.x+right,base.y+top)` supply depth keys `(tile.top+tile.bottom)>>1 − origin_y`. Equal keys need one sprite; unequal keys split the sprite into vertical clips so a long building interleaves correctly with neighboring people/objects. Opposite-corner horizontal distances `d1,d2` give span=`2*min(d1,d2)` and key step=`±span/4`, negative when d2<d1. The first strip ends at `A.left+3span/4`; subsequent edges step span/2, with the final strip covering the remaining view. Scratch keys `0x00801b40`, clips `0x00800400` and count `0x00801b24` reset per object. [renderview.c](../../LEGOLAND/renderview.c)

ObjDef flag `0x20` enables `+0xa8(ctx)` once per class before queuing. Flag `0x400` requests `+0xa0(ctx,base)` for its descriptor; missing callback/result skips the object. Otherwise sprite `+0x64` and offsets `+0x14/+0x18` supply it. Cell `0x20` means construction: context `0x104`, build animation `+0x6c` with signed class-byte offsets `+0x32/+0x33` and build frame override, or normal sprite tinted `0xff00`. Other objects use context `0x103`; flag 4 suppresses warning tint, disconnected `0x200` blinks `0xff0000`, no-power `0x100` blinks `0xffff` on the opposite phase when power is enabled. [renderview.c](../../LEGOLAND/renderview.c)

`PaintTileLayer` paints terrain under everything else, followed by perimeter/bridge pieces. It derives the top-left diamond from scroll quotient/remainder and chooses one of four quarter-diamond corrections using selector `1+(xrem>=halfw)+2*(yrem>halfh)`. A cell satisfying object flags `0x3` and `0x8` with custom `+0xa0` is skipped for the object pass; without that callback it gets only its tile. Other path cells also receive path overlay. The second cell's no-callback arm incorrectly paints at the first cell's `(px,py)` instead of half-tile offset. Render-node table `0x00807f60` has 4096 `{live,packed_base,x,y}` entries; taking a node returns its saved scan-resume position and retires it, or map width/height when absent. [render4.c](../../LEGOLAND/render4.c)

Terrain/perimeter list head is `0x00667ca8`; nodes use packed frame `+0x10`, world pixel x/y `+0x14/+0x18`, next `+0x1c`, bound sprite-bank entry `+0x20`. Frame high byte zero selects base bank `0x00667cac`, nonzero selects bridge bank `0x00667cb0`; low byte is bank index/bridge half. Binding caches the entry and starts type-2/3 animations with more than one frame. A missing bridge bank leaves no sprite. ### Overview map

The overview is a 640×340 function sprite at view origin `(0,32)` and view record `{h=340,w=640,x=0,y=32}` at `0x008139c0`. `0x00667c30` is called `g_fullmap_busy` by the renderer and `g_ms_ready` by the screen. Cross-reading resolves it as a **cached-map readiness latch**: successful rendering sets it, initialization checks it, and `KillMapScreen` clears it. It is not a requirement to redraw a fresh map on every call. A repeated callback still loads three temporary sprites and creates a pen before checking readiness and returning, leaking them. [renderview.c](../../LEGOLAND/renderview.c), [mapscreen.c](../../LEGOLAND/mapscreen.c)

Overview rendering temporarily builds the full-map render chain (including driving-school road cells with `0x8`), zeros the map view origin, fills black and paints terrain, object cells, perimeter and the render chain. It restores origin/clipping and the normal world render chain afterward. World extents are ox=`−map.height*tw/2`, oy=0, spanx=`map.width*tw/2−ox+1`, spany=`(map.width+map.height)*th/2+1`; fixed scales are `(640<<16)/spanx` and `(340<<16)/spany`. Tile wash dimensions initially are integer `640*tw/spanx+1` and `340*th/spany+1`, but these two globals are later reused for individual sprite dimensions. [renderview.c](../../LEGOLAND/renderview.c), [render3.c](../../LEGOLAND/render3.c)

World-to-overview projection adds back `scroll>>8`, subtracts ox/oy, multiplies by 16.16 scale and adds vertical centering cy. The recovered cy is `(340-(((mapw+maph−2)*((th+1)>>1)−oy)*640/spany/2))>>1`; the division/shift distinction matters for negative values. The reverse mouse helper uses `map_x=(px−view.x)*spanx/view.w+ox` and `map_y=(py−cy−view.y+1)*spany*2/view.w+oy`. Each wash block begins at `(mx−7,my−2)` with dimensions `(cw+5,ch+4)`. [renderview.c](../../LEGOLAND/renderview.c), [mapscreen.c](../../LEGOLAND/mapscreen.c)

### 3D math, ramps and pixels

Float and 16.16 matrices are row-major 3×3 arrays and multiply column vectors. Y rotation is `[c,0,s; 0,1,0; −s,0,c]`; person matrices are stored at `+0x58` and flip the middle entry to −1. Person rotation vector is `+0x40..+0x48`. Handedness is the sign of `(row0×row1)·row2`. `ArcTan256` gives 0..255 turn units, with x=0 returning 64/192, otherwise atan2 scaled by `256/(2*3.1415926)` then rounded using floor(a+0.5). Depth helper uses `49152/(near−far)` and offset 8192. [math3d.c](../../LEGOLAND/math3d.c)

Triangle output uses four fillers: flat, Gouraud, flat-textured and Gouraud-textured. They sort vertex **pointers** by y without rearranging caller records, then rasterize upper/lower halves with affine 16.16 edge interpolation. The long edge continues through the split; the short edge changes slope without resetting accumulated error. Reciprocals are `recip[n]=int(65536/n)` for n=1..99 and floats `1/n` in a parallel array indexed n−1. Spans use `recip[(dx>>16)+1]`. Vertical/horizontal clipping fast-forwards all interpolants; scanline bounds use y<end and y<=clip.bottom, span loop x<right and pixel pointer<=clip.right. [tri3d.c](../../LEGOLAND/tri3d.c)

The private Z buffer is 128×120 dwords (`0xf000` bytes, pitch `0x200`). An unsigned greater-or-equal comparison wins, so larger depth is nearer and later triangles win equal-Z ties. The model window is 160×120, so coordinates beyond the 128-wide Z plane can alias. `RenderZBufferObject` clears depth then seeds scenery occlusion via `ZBufferHelper`; its sprite Z frames use four-bit control units, with frame-0 data starting after a 512-byte table at +`0x208`, later at +8, and Z in the dword's high byte. Mouse picking compares written pixel address with the stored mouse address. [tri3d.c](../../LEGOLAND/tri3d.c), [bigrender.c](../../LEGOLAND/bigrender.c)

Coaster occlusion commands are distinct from sprite Z frames: `{int n; short ylast; short reserved; {short x; short y; int step;} v[n]}`, stride `8+8n`. The sign of vertex y selects left/right chain and its magnitude is the scanline. The decoder has eight keys and eight `0x30`-byte edges; the producer must provide scanline order. Last edge ylast is initialized to command ylast−1; the fill increments it and writes a sentinel key at key[n]. Zero/negative counts write before edge[0]; the command producer emits no empty command. [schoolcar5.c](../../LEGOLAND/schoolcar5.c), [schoolcar6.c](../../LEGOLAND/schoolcar6.c)

Ramps cache by the caller's three color bytes, whose physical packing is B,G,R: low 5 bits for byte0, green bits for byte1, top 5 for byte2. Channel tables for i=0..255 are `c0=floor(i*31/256)`, `c1=floor(i*max/256)<<5`, `c2=floor(i*31/256)<<(greenBits+5)`, max=`255>>(8−greenBits)`; greenBits=6 gives 565, 5 gives 555. Each levels/2-entry half interpolates black→base and base→white with accumulators emitted before increment, so the last sample approaches rather than reaches full white. Runtime callers typically use 64 levels. Shade index is `shade>>10` (equivalent to high16(shade<<6)); shade 1.0 indexes 64, outside that ramp. `ShadeLookup` is a different helper using `int((levels−1)*t)`. [tri3d.c](../../LEGOLAND/tri3d.c)

Texture u/v are float-normalized at input, converted as `(int(uv*65536)&0xffff)<<shift`; exact 1.0 wraps to zero. Texel address is `(high16(u)<<ushift)+high16(v)`, then its byte chooses a shade ramp. Gouraud texturing applies u/v masks and repeats; flat texturing ignores masks. Neither path performs perspective correction, shade clamp or general bounds clamp. Initialization order is pixel format/channel/Z/reciprocal setup, target per lock, mouse per frame, Z seed per model, then flat-color/texture selection and triangles. [tri3d.c](../../LEGOLAND/tri3d.c)
