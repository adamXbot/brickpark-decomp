# Callback registration and current implementation names

This index records explicit class-registration assignments at the Scope J baseline. In direct-registration rows, an omitted slot retains its earlier value. Library rows follow the separate null-clearing rules below. Addresses identify the original executable, and linked names come from current `FUNCTION` / `WIP-FUNCTION` definitions. Provider aliases are retained when they differ. A linked body can still contain an unknown or placeholder tail; registration evidence does not certify complete behavior. [screen.c](../../LEGOLAND/screen.c), [interfaces.c](../../LEGOLAND/interfaces.c), [RIDE_CALLBACKS.md](../RIDE_CALLBACKS.md)

## Layout, dispatch order and slot roles

ObjDef is `0xd0` bytes, reached through the class element at`+0c`. The ODF loader installs standard callbacks, then chooses a branch. With flag`0x10000` and a nonempty DLL name, successful library loading skips `SetCustomCallbacks`; failure clears that flag, runs custom registration, invokes `+a4` if present and reports the load error. Without a requested DLL it runs custom registration, with no explicit `+a4` call at this site. All paths later call the external `ObjDefFinalize`; its body is absent, so ordinary initializer ownership is not inferred. The custom name-chain is followed by18 providers in this order: CastleLevel1, LogFlume, Copters, Fort, GoldRush, Temple, Catapult, Joust, TempleSlide, SpiderRide, SafariRide, WaterWorks, Garden, WesternTown, SpaceTower, SpinningBarrels, PlaneRide, CastleObj. The last write to a slot wins. [llidb_odf.c](../../LEGOLAND/llidb_odf.c), [screen.c](../../LEGOLAND/screen.c)

| Offset | Recovered use |
| --- | --- |
| `+8c` | selection / placement tick; legacy “Tick” names do not imply simulation |
| `+90 / +94` | additional placement updates; used by more classes than the old flume-only header suggests |
| `+98 / +9c` | add / remove a map instance |
| `+a0` | render descriptor override, class flag`0x400` |
| `+a4` | class resource initialization |
| `+a8` | class simulation, class flag`0x20` |
| `+ac` | class resource teardown |
| `+b0` | custom draw / interaction overlay, sprite flag`0x2000` |
| `+b4` | library slot preserved here without an inferred universal role |
| `+b8 / +bc` | class save-chunk reader / writer |
| `+c0` | additional class-specific operation |

The slot meanings follow consumers and provider declarations. [interfaces.c](../../LEGOLAND/interfaces.c), [savegame.c](../../LEGOLAND/savegame.c), [llidb_odf.c](../../LEGOLAND/llidb_odf.c)

Standard slots are`+8c=0x480b70`, `+90=0x45fa80`, `+94=0x480bb0`, `+98=0x45efe0`, `+9c=0x45f220`. The loader initially zeroes the ODF record, then reads its size-delimited header before registration; `SetStandardCallbacks` itself writes only these five slots. [sweep3.c](../../LEGOLAND/sweep3.c), [llidb_odf.c](../../LEGOLAND/llidb_odf.c)

The library table has14 pointers, but is **not** a contiguous copy of ObjDef slots: index7 is an initializer invoked immediately and never stored at`+a4`; indices0–6 map to`8c,90,94,98,9c,a0,a8`; indices8–13 map to`ac,b0,b4,b8,bc,c0`. Nonnull values replace earlier slots except`b4/b8/bc`, which are always stored, including null. The three boating rows below are shown separately for this alternate provider path. Library nodes are16 bytes `{next,module,reference count,provider}`, head`0x00669244`. [loaders.c](../../LEGOLAND/loaders.c)

## Original quirks and boundaries

Garden class matching uses case-sensitive `strcmp` for `HEDGE` and `FLOWERS`; other providers shown use case-insensitive `NameCompare`. Castle track rows use shared thunks plus a second row table: the final assignment changes `SQUARE_TRACK +90` to `Track_Update90`, and load/save dummy `+8c` to their serializer. The table below preserves those last writes. It does not erase the intermediate dispatch-row setup described in [attractions](attractions.md) and [transport](transport.md). [interfaces.c](../../LEGOLAND/interfaces.c), [castleobj.c](../../LEGOLAND/castleobj.c)

Fountain, power-station and dinosaur branches also call their sound initializers immediately; those calls are not stored callback slots. Unrecognized names do not acquire castle callbacks merely because the provider is called. Class-specific callback semantics, saved record layouts, original failures and external tables belong to the subsystem pages. [screen.c](../../LEGOLAND/screen.c), [castleobj.c](../../LEGOLAND/castleobj.c)
